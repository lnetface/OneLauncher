# Agent参与该项目代码编写必须知道的注意事项
项目的Github地址是 https://github.com/lnetface/OneLauncher
1. 必须阅读该文档
2. 必须阅读 AI_Instructuion 文件夹下的所有文档
3. 推荐使用文件系统而不是Git的方式来访问项目文件
4. 代码应进行最小化更改（致命Bug修复、错误处理例外）
5. 必须为项目的AOT编译做适配

## 项目文件结构说明
项目根目录下：
- 小写字母的文件夹代表非代码部分 e.g docs,build
- 驼峰命名法的文件夹代表实际代码部分 e.g OneLauncher.Core
- 实际代码部分文件夹命名为OneLauncher.XXX（`.`代表的是命名空间）
非实际代码部分文件夹（目前项目根目录下只允许存在这几个非代码部分文件夹）：
- docs ：项目文档
- build ：构建相关文件
    - build 文件夹包含基础发布配置、脚本等。
    - 对于复杂任务，如实验等，其中的调试任务在此进行。每个具体任务在build文件夹内新建自文件夹，按任务名称和日期命名。
- ConsoleTest/agent_test ；Agent专用测试文件夹
    你可以在该文件夹内新建各个自项目，包含各个测试项目。

**测试和实验完毕后应该调用清理脚本 build/clean.ps1 进行清理**

## docs 文件夹子目录说明
- A ：由人类编写的文档
- Old ：已过时的文档（ai_gen的文档不会被归到此）
- AI_Generated （简称ai_gen）：Agent在完成完功能编写后必须生成一份文档到该处，说明代码用意、逻辑、如何对未来开放可拓展性；Agent在编写代码时，考虑到部分代码由Agent编写无文档说明，可以在此处查看文档说明
- AI_Instruction （检查ai_instr）：项目对Agent代码编写的要求

## 项目的前后端配合
一般而言，项目的前端部分（多数为.axaml）部分由Agent设计，后端部分为保证可拓展性人项目贡献者亲自操刀。
在人类设计后端时，可能有所不足，导致Agent在设计前端时出现问题。
比如说在之前的代码中TaskManager没有设置OnTaskCreated事件，导致Agent在设置前端（ViewModel）时使用了不恰当的轮询逻辑。
所以如果Agent在设计代码时，发现后端的设计不足以使前端的设计可以解耦，应当中断任务并要求人类修改完后端代码后再继续执行
