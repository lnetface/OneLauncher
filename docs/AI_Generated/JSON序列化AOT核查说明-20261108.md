# JSON 序列化 AOT 核查说明

日期：2026-11-08

已检查 `OneLauncher.Core`、`OneLauncher` 的实际 JSON 读写入口、源生成上下文和自定义转换器，未发现需要改为源生成的生产调用。此前仅凭缺少推荐模组类型的独立 `JsonSerializable` 声明推测缺少 AOT 支持不成立。

## 源生成证据

配置通过 `DBManager.CreateJsonTypeInfo` 获取 `OneLauncherAppConfigsJsonContext.AppConfig`，`BasicDataManager` 的异步保存和读取均显式传入 `JsonTypeInfo<T>`。

`AppConfig` 引用 `DefaultConfig`，后者引用 `List<RecommendedMod>`。源生成器自动递归生成 `RecommendedMod`、`ModLimited`、`ModType`、`Than` 及该列表的类型信息。此次输出生成代码，确认上述类型的 `.g.cs` 文件和 `GetJsonTypeInfo` 分派均存在；无需额外添加重复的类型注册。

`GameDataJsonContext` 中存在 `Guid?` 转换信息及匹配的构造参数、属性访问代码，支持 `DefaultUserModelID` 为空。`Than` 使用源生成的泛型枚举转换器，当前 JSON 保持数值 0/1，与旧配置兼容。

Modrinth、Minecraft、Fabric/Quilt、Forge、整合包、账户认证的生产读写入口均使用源生成信息。Minecraft 的两处自定义转换器手动处理 JSON Token，嵌套对象读写也显式传入类型信息。`MojangProfile.cs` 中无上下文的序列化示例位于块注释中，不执行。

## 验证范围

新增 `ConsoleTest/JsonAotChecks.cs` 与 `--json-aot` 入口，测试不使用反射、Debug 专用 setter 或真实启动器初始化。设置 `JsonSerializerIsReflectionEnabledByDefault=false` 后，1686 项 JIT 检查通过，覆盖：

- 当前默认推荐清单通过真实 DBManager 保存、读取，项目 ID、顺序、版本、比较条件和四种加载器标志逐项一致。
- 自定义项目 ID、slug、两种比较枚举保持 JSON 格式及往返值。
- 旧列表保持已保存的值；缺少推荐属性时采用新默认清单，邻近设置保留。
- 可空与具体账户 ID、实例 ID 恢复及运行时路径忽略。
- Modrinth 文件、哈希与依赖的源生成读写。

检查数量随默认清单长度变化，不应把 1686 写成测试期望值。JIT 的运行时配置确认 JSON 反射开关为 false，检查本身也验证该值。

Windows x64 Native AOT 专用测试程序发布成功，运行 `ConsoleTest.exe --json-aot` 同样通过 1686 项检查，退出码为 0。发布目录存在原生 EXE，不含 `ConsoleTest.dll` 或 `coreclr.dll`，确认运行的是 Native AOT 产物。构建和发布仍有现有编译警告，不应据此声称整个工程零警告；本次没有进行完整桌面应用启动、认证或网络下载测试。

## 测试与生产的区别

`ConsoleTest/ForgeIntegrationTests.cs` 与 `tests/OneLauncher.ForgeTests` 中仍有无源生成信息的测试结果导出。它们不在桌面生产路径内，不能据此判断推荐模组配置不支持 AOT；若将完整测试集发布为 AOT，需要另行适配。这次原生验证复用 `JvmConfigAotOnly=true` 排除旧集成夹具，JSON 入口放在专用分支之前。

此前 26.2 只下载旧清单的问题来自配置文件已有列表覆盖源码默认值，与源生成和 AOT 支持无关。

修改仅涉及 `ConsoleTest/JsonAotChecks.cs`、`ConsoleTest/Program.cs` 和测试说明文档，生产序列化实现未更改。测试夹具、生成代码与构建产物均位于工作区内，检查后清理。
