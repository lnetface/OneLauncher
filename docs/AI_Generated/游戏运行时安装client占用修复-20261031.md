# 游戏运行时安装实例：client 文件占用修复

## 问题
游戏运行时导入整合包，`RaceDownloader.ReadResponseAndWriteToFileAsync` 在 `File.Move(..., overwrite: true)` 覆盖 client jar 时抛出 `UnauthorizedAccessException`。

## 原因
`DownloadMinecraftPlanner.CreateDownloadPlan` 中的跳过逻辑写成了 `File.Exists(clientFile.Value.sha1)`，传入的是 SHA1 字符串而不是文件路径，条件永远为假，client 始终会重新下载并覆盖正在被 JVM 占用的文件。

## 修改
- `Download.IsSha1Matched`：新增只返回校验结果的方法，以 `FileShare.ReadWrite` 打开文件，兼容其他进程已持有的句柄。
- `DownloadMinecraftPlanner`：改为检查 `clientFile.Value.path`；SHA1 一致时将 `ClientMainFile` 置空跳过下载，不一致时保留下载项按损坏文件重新下载（不再直接抛出致命异常）。

## 限制
若 client 文件 SHA1 不一致且正被运行中的游戏占用，覆盖仍会失败，此时需要用户关闭游戏；启动器不会结束游戏进程。
