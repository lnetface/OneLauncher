# Quilt 可空映射元数据兼容

## 问题与行为

本地 Minecraft 26.2 的 Quilt 元数据中 `intermediary` 和 `hashed` 为 null，而旧版 1.21.5 包含这两个映射对象。解析器此前始终解引用两个对象，导致生成下载计划时发生空引用异常；启动类路径生成也存在相同问题。

## 修改文件与逻辑

- `OneLauncher.Core/DefaultComponent/Resource/Mod/Loader/Fabric/JsonModel.cs`：将 `FabricRoot.Intermediary` 和 `FabricRoot.QuiltHashed` 标记为可空，与元数据实际结构一致。继续使用现有源生成 JSON 上下文，兼容 AOT。
- `OneLauncher.Core/DefaultComponent/Resource/Mod/Loader/Fabric/quilt/QuiltNJParser.cs`：下载阶段仅在映射对象存在时添加对应库；启动阶段通过可空访问跳过不存在的映射库。旧版包含映射对象时继续使用 Fabric / Quilt 仓库。核心库的 Maven 坐标格式错误时报告明确异常。

Loader 和通用依赖仍按原逻辑加载。未来扩展其他可选映射时，应同时更新下载清单与启动类路径，避免安装成功但启动失败。

## 验证范围

按项目要求，本次小范围兼容修改不运行测试。静态检查覆盖下载及启动两处映射对象访问；未进行实际游戏下载、启动或 AOT 构建。
