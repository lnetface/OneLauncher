# 资源地址集合与非微软登入开关

日期：2026-11-13。这是“云资源更新同步”功能的后端模型准备，见 [可行性研究](云资源更新同步可行性研究-20261113.md)。本次只新增配置模型并适配现有调用点；不包含远程清单请求和写入 `config.json` 的代码，也未改动 `AutoUpdate.CheckUpdate` 的最新版本请求方式。

## 模型（`Global/ModelDataMangers/DBManager.cs`）

`DefaultConfig` 新增两个成员：

- `Resources`（`ResourceCollection`）：资源地址集合。属性初始值即启动器默认值，网络资源同步时直接覆盖。
- `AllowNonMicrosoftLogin`：是否允许离线、外置等非微软账户登入，默认 `true`。

`ResourceCollection` 的每项都是按顺序尝试的候选地址列表：

| 属性 | 用途 |
| --- | --- |
| `Updater` | Windows 更新脚本 `install.ps1` |
| `ConnectCore` | MCT 联机核心 |
| `SkinGetterWithUUID` | 皮肤全身渲染图，使用时在地址后拼接 UUID |

`ResourceCollection` 已加入 `OneLauncherAppConfigsJsonContext`。删除了已无读取方的 `DefaultConfig.CrafatarUrl`，旧配置中的该键在读取时被跳过。

## 多地址请求（`DefaultComponent/Downloader/Download.cs`）

- `HttpStreamGetter(IEnumerable<string> urls, CancellationToken)`：按顺序请求，返回第一个成功响应的流。取消时立即传播；全部失败时原样抛出最后一个地址的异常。非文件形式的资源可以直接使用此方法。
- `DownloadFile(IEnumerable<string> urls, ...)`：基于上面的方法下载到文件。原有的单地址 `DownloadFile` 转调这个重载，行为不变（空地址仍直接返回）。
- 修复：原 `HttpStreamGetter(string)` 在返回流之前调用了 `response.Dispose()`，这会连同 `Content` 释放刚取得的流，导致 `DownloadFile` 在复制时失败。现在只在请求失败时释放 `response`；成功时由调用方释放流来归还连接。

重试只覆盖“取得响应”这个阶段（连接失败、非成功状态码）。已开始读取正文后发生的中断，不会切换到下一个地址。

## 调用点

| 文件 | 变化 |
| --- | --- |
| `Global/AutoUpdate.cs` | `Update()` 使用 `Resources.Updater`，移除 `UpdaterUrlWindows` 常量 |
| `ConnectToolPower/MCTPower.cs` | 使用 `Resources.ConnectCore`，移除 `CoreUrl` 常量；MD5 仍内置、流程不变，因此只在下载失败时换地址，下载成功但校验不符时仍按原逻辑报错 |
| `Account/Microsoft/MojangProfile.cs` | `GetSkinHeadImage()` 对每个地址拼接 UUID 后依次尝试；删除了引用旧 `CrafatarUrl` 的注释代码 |

## 非微软登入开关

只在 UI 层 `UserModelLoginPaneViewModel` 中检测：

- `RLogin()`（外置登入）：在已有 try 块内、发送账号密码之前抛出 `OlanException`，由原有的 catch 展示。
- `Done()`（离线账户）：这是没有 try/catch 的同步命令，项目也没有全局异常处理，直接抛出会成为未处理异常。因此在这里构造 `OlanException` 后直接交给 `OlanExceptionWorker` 展示，然后返回。

后端不做拦截：已保存的离线/外置账户在开关关闭后仍可启动游戏。

## 扩展

- 远程清单同步：将清单中非 null 的字段赋值给 `DefaultSettings.Resources` 的对应属性和 `AllowNonMicrosoftLogin`，再调用 `DBManager.Save()`。
- 新增资源：在 `ResourceCollection` 中添加带初始值的 `List<string>` 属性；调用方使用 `HttpStreamGetter(urls)` 或 `DownloadFile(urls, ...)`。
