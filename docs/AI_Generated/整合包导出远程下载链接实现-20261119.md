# 整合包导出远程下载链接 · 实现说明-20261119

> 对应行动文档：`整合包导出远程下载链接行动文档-20261119.md`。方案依据：《Mod JAR 来源解析与整合包导出方案》。

## 1. 用意

导出实例为 `.mrpack` 时，不再把 `mods/` 中所有模组都打包进 `overrides/`：

- 能按**文件哈希**在 Modrinth / CurseForge 精确识别的模组，写入 `modrinth.index.json` 的 `files[]`（下载链接、SHA-1、SHA-512、大小），导入时在线下载；
- 无法识别的模组（自编译、私有、已被平台替换等）仍打包进 `overrides/mods/`，导出的整合包始终完整。

对外入口改为 `OneLauncher.Core.Services.ResourceInstallerService.ExportModpackAsync`，`ModpackExporter` 降为 `internal`。

## 2. 执行逻辑

```text
ResourceInstallerService.ExportModpackAsync
 └─ ModpackExporter.ExportAsync
     ├─ ModSourceResolver.ResolveAsync(<实例>/mods)
     │   ├─ 扫描顶层 *.jar / *.jar.disabled
     │   ├─ 并行（上限 ProcessorCount）一次读取：size + SHA-1 + SHA-512
     │   ├─ Modrinth  POST /v2/version_files（sha512，每批 500）
     │   │     在版本 files[] 中按 sha512 找到同一文件，核对 size、sha1，链接须为 https
     │   ├─ 未命中 且 Init.CurseforgeApiKey 已配置：
     │   │     CurseForgeFingerprint.ComputeAsync（Murmur2，seed=1，过滤 09/0A/0D/20）
     │   │     POST /v1/fingerprints/432，只用 exactMatches
     │   │     核对 fileFingerprint、fileLength、sha1；downloadUrl 为空或非 https 视为未命中
     │   └─ 返回 (RemoteFiles: 完整路径→ModrinthFile, UnmatchedCount, Warnings)
     ├─ 枚举实例文件，排除 RemoteFiles 中的文件 → overrides/
     ├─ 清单 files[] = RemoteFiles（按 path 排序；path 为 mods/<文件名>，保留 .disabled）
     └─ 临时文件写完后原子替换 → ModpackExportResult
```

### 失败降级

| 情况 | 处理 |
| --- | --- |
| Modrinth / CurseForge 网络错误、HTTP 错误、JSON 错误、超时、CF 鉴权失败 | 该平台按“全部未命中”处理，写入 `Warnings`，导出继续 |
| 未配置 CurseForge API Key（且有未命中的模组） | 跳过 CF，写入一条提示 |
| 用户取消 | `OperationCanceledException` 向上传播，删除临时文件 |
| 文件读写错误 | 转为 `OlanException("导出失败", ...)`（沿用原逻辑） |

从不根据文件名或模组 ID 推测地址。

## 4. 兼容性说明

- `ModrinthManifest` 的 `game`、`versionId`、`name`、`dependencies` 和 `ModrinthFile.path` 标为 `required`。System.Text.Json（.NET 8+）会在这些字段缺失时抛出 `JsonException`，`MrpackParser` 会把它转换为“解析失败”。原来这种情况会在后面的流程里出现 NRE 或空名称。
- 导出的清单现在总会写出 `files`（可能是空数组），符合 mrpack 规范。
- 来自 CurseForge 的链接位于 `forgecdn.net`。OneLauncher 和 Prism 能正常导入，但**上传到 Modrinth 平台**时，可能因为下载域名白名单而被拒绝。
- 前端进度分两个阶段（来源识别和打包），各自从 0 计数。

## 5. 扩展点

- **用户自定义 URL 映射**：在 `ModSourceResolver.ResolveAsync` 中 CurseForge 步骤之后追加一步，对仍未命中的文件按“路径 → url + 哈希”映射生成条目。
- **resourcepacks / shaderpacks 参与反查**：把扫描目录参数化，`CreateEntry` 中的 `mods/` 前缀改为由调用方传入。
- **CurseForge `manifest.json` 格式导出**：需要在解析结果中额外保留 CF 的 `modId/fileId`，目前只保存了 URL。
- **候选确认界面**：在 `CurseForgeFingerprintMatchesResult` 中声明 `partialMatches`，交给前端确认。

## 6. 验证

- **没有编译。** 当前环境没有 .NET SDK，并且 dotnet / NuGet 下载地址都被网络策略拦截。以下 API 需要在本机编译时确认：`ZipArchiveEntry.OpenAsync`、`ZipArchive` 的 `IAsyncDisposable`（.NET 10 新增）、`Convert.ToHexStringLower`（项目中已有使用）。
- 已用 Python 对拍：流式、分块的 Murmur2 移植与经典整段实现，在 300 组随机数据、4 种分块大小下结果一致（含空白过滤和尾部 1–3 字节）。**没有**用 CurseForge 真实文件指纹核对。
- 静态检查：`ModpackExporter` 只有 `ResourceInstallerService` 一处引用。回归测试中 `ModpackUiChecks` 的清单夹具包含所有 `required` 字段。`GetModpackCurseForge` 构造的 `ModrinthFile` / `ModrinthManifest` 满足新的 `required` 要求。
- 建议在本机执行：

```powershell
dotnet build OneLauncher.Core/OneLauncher.Core.csproj --nologo
dotnet build OneLauncher/OneLauncher.csproj --nologo
```

然后手动导出一个同时包含 Modrinth 模组和自编译 jar 的实例，检查 `modrinth.index.json` 的 `files[]` 和 `overrides/mods/`，再把它导入为新实例，对比模组文件。
