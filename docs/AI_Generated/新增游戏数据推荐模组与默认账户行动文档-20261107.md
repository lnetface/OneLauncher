# 新增游戏数据推荐模组与默认账户行动文档

日期：2026-11-07

本文档只说明计划执行的操作和涉及的文件，本轮没有修改任何项目代码。标注“需要人工后端实现”的部分位于 `OneLauncher.Core`，按项目惯例交给人工完成；前端部分位于 `OneLauncher`，不改动 `OneLauncher.Desktop`。

## 一、目标

1. 在新增游戏数据面板（`NewGameDataPaneViewModel`）的“实例信息”下方增加“工具”板块，提供“一键安装所有推荐模组”复选框。勾选后，游戏数据创建成功时，启动器在后台从 Modrinth 下载推荐模组，并按实例的模组加载器（Fabric、Quilt、Forge、NeoForge）和游戏版本自动挑选兼容版本。
2. 游戏数据的默认登录账户允许为空。为空时，启动游戏使用全局默认账户。

## 二、现状分析

### 2.1 新增游戏数据面板

`OneLauncher/ViewModels/Panes/NewGameDataPaneViewModel.cs` 的构造函数接收 `VersionListManager`、`AccountManager`、`GameDataManager`、关闭回调和可选的 `UserVersion`，由 `NewGameDataPaneViewModelFactory` 从 `UnitedCore` 取服务后创建。

`Save()` 的顺序是：校验输入，`new GameData(name, versionId, loader, userModel: SelectedUser.UserID)`，`AddGameDataAsync`，弹出提示，关闭面板。这里适合在保存成功后启动推荐模组安装任务。

`OneLauncher/Views/Panes/NewGameDataPane.axaml` 的布局为：标题，ScrollViewer 中依次是“基础版本”和“实例信息”（名称、加载器、默认用户），底部是取消/创建按钮，启用了 `x:CompileBindings="True"`。新板块放在“实例信息”之后即可。

### 2.2 Modrinth 下载能力

`OneLauncher.Core/DefaultComponent/Resource/ResourceGetterService/Modrinth/GetModrinth.cs` 已提供按模组 ID、游戏版本、加载器类型查询兼容版本的能力：

- 构造：`GetModrinth(string ModID, string version, ModEnum modType, string modPath)`
- `Init(CancellationToken, bool includeDependencies = true)`
- `GetDownloadInfos()` 返回 `NdDowItem?`，没有兼容版本时为 null
- `GetDependenciesInfos()` 返回依赖下载项

`OneLauncher.Core/DefaultComponent/Resource/ResourceFileInstaller.cs` 的静态 `InstallAsync(...)` 可以执行批量下载，并以 `(int completedFiles, string FilesName)` 报告进度。推荐模组安装直接复用这两者，不新写下载逻辑。

### 2.3 默认账户

- `OneLauncher.Core/Helper/Models/GameData.cs` 第 20 行 `DefaultUserModelID` 是 `Guid`，不能表示“空”。
- 同文件第 48 行的构造函数在 `userModel` 为 null 时回落到 `AccountManager.GetDefaultUser().UserID`，所以就算传入 null 也会被写成具体账户。
- `AccountManger.cs` 中全局默认账户 `AccountData.DefaultUserID` 已经是 `Guid?`；`GetDefaultUser()` 在没有默认用户时抛出 `OlanException("没有默认用户")`。
- `GameLauncher.cs` 第 48 行在找不到实例指定的账户时直接抛出“找不到你想要启动的用户”。
- `EditGameDataPaneViewModel.cs` 第 58-63 行在账户不存在时把全局默认账户写回实例，第 90 行用 `SelectedUser!.UserID` 保存。

## 三、功能一：一键安装推荐模组

### 3.1 推荐模组清单（需要人工后端实现）

新增 `OneLauncher.Core/DefaultComponent/Resource/RecommendedMods/RecommendedModCatalog.cs`，用常量列表按加载器维护 Modrinth slug，方便以后人工调整：

| 加载器 | 推荐模组（Modrinth slug） |
|---|---|
| Fabric | fabric-api、sodium、lithium、iris、modmenu |
| Quilt | qsl（失败时回退 fabric-api）、sodium、lithium、iris、modmenu |
| Forge | embeddium、modernfix、ferritecore |
| NeoForge | embeddium、modernfix、ferritecore |

清单只是静态数据，不使用反射，满足 Native AOT。

### 3.2 安装服务（需要人工后端实现）

新增 `OneLauncher.Core/DefaultComponent/Resource/RecommendedMods/RecommendedModInstaller.cs`，对外提供：

```csharp
Task<RecommendedModInstallResult> InstallAsync(
    GameData gameData,
    IProgress<(int completed, int total, string fileName)>? progress,
    CancellationToken token);
```

处理流程：

1. 根据 `gameData.ModLoader` 取清单，加载器为 none 时直接返回。
2. 对每个 slug 创建 `GetModrinth(slug, gameData.VersionId, loader, Path.Combine(gameData.InstancePath, "mods"))`，调用 `Init(token, includeDependencies: true)`。
3. 汇总 `GetDownloadInfos()` 和 `GetDependenciesInfos()`，按文件名或项目 ID 去重，避免依赖重复下载（例如多个模组都依赖 fabric-api）。
4. 没有兼容版本或查询失败的模组记入“已跳过”列表，不中断其他模组。
5. 调用 `ResourceFileInstaller.InstallAsync` 下载到实例的 `mods` 目录，转发进度。
6. 返回结果：成功数量、跳过的模组名、失败的模组名。

在 `OneLauncher.Core/Global/Init.cs` 注册该服务，使 `UnitedCore` 可以取到它。

### 3.3 前端改动

`NewGameDataPaneViewModel.cs`：

- 新增 `[ObservableProperty] bool InstallRecommendedMods`。
- 新增 `CanInstallRecommendedMods`，当 `SelectedModLoader` 不为 `ModEnum.none` 时为 true；在 `OnSelectedModLoaderChanged` 中通知更新，切回原版时自动取消勾选。
- 构造函数增加 `RecommendedModInstaller` 和 `TaskManager` 参数。
- `Save()` 中游戏数据成功加入后，如果勾选了复选框，就仿照 `DownloadPaneViewModel` 和 `InstallPackPaneViewModel` 的写法，用 `TaskManager.CreateTask()` 取得 Token，再 `Task.Run` 执行安装。面板照常关闭，安装在任务中心后台进行。
- 安装结束后用 `MainWindowShowFlyoutMessage` 提示结果，例如“已安装 6 个推荐模组，跳过 iris（没有适配 1.21.x 的版本）”。异常通过 `OlanExceptionWorker.ForOlanException` 和 `ForUnknowException` 处理。
- 模组安装失败不回滚游戏数据，只提示失败原因。

`NewGameDataPaneViewModelFactory.cs`：两个 `Create` 重载都从 `UnitedCore` 取新服务并传入。

`NewGameDataPane.axaml`：在“实例信息”区块之后加入：

```xml
<TextBlock Classes="pane-section-title" Text="工具" />
<Border Classes="pane-surface">
    <StackPanel Spacing="6">
        <CheckBox Content="一键安装所有推荐模组"
                  IsChecked="{Binding InstallRecommendedMods}"
                  IsEnabled="{Binding CanInstallRecommendedMods}" />
        <TextBlock Classes="pane-label"
                   Text="创建后从 Modrinth 自动下载与当前加载器和版本兼容的常用模组" />
    </StackPanel>
</Border>
```

没有选择加载器时复选框禁用，并显示“需要选择模组加载器”的提示文字。

## 四、功能二：默认账户可以为空

### 4.1 数据模型（需要人工后端实现）

- `GameData.cs`：`DefaultUserModelID` 改为 `Guid?`，删除构造函数中回落到全局默认账户的逻辑，传入 null 就保存 null。旧配置中已有的 Guid 可以正常反序列化为 `Guid?`，不需要迁移。
- 检查 `GameData` 所在的 `JsonSerializerContext`（可用 `rg -l "JsonSerializerContext"` 定位），确认可空类型已被源生成覆盖。

### 4.2 账户解析（需要人工后端实现）

在 `AccountManger.cs` 新增：

```csharp
public UserModel? ResolveLaunchUser(Guid? gameDataUserId)
```

规则：实例账户不为空且存在时返回它；为空或已被删除时返回全局默认账户；全局默认账户也不存在时返回 null。顺带修正 `GetDefaultUser()` 的可空性标注。

### 4.3 启动流程（需要人工后端实现）

- `GameLauncher.cs` 第 36 行和第 48 行改用 `ResolveLaunchUser`。只有在实例账户和全局默认账户都不存在时，才抛出 `OlanException`，提示“没有可用账户，请先登录或设置全局默认账户”。
- `GameArgsBuilder.cs` 第 16 行已有回落逻辑，只需适配 `Guid?`。
- 以下位置创建 `GameData` 时可以改为传 null，让新实例默认跟随全局账户：`ImportMain.cs` 第 52 行、`DownloadInfoCreater.cs` 第 48-61 行、`GameDataManger.cs` 第 114 行、`ModpackImporter.cs` 第 93 行。这一项可选，不改也能正常编译运行。

### 4.4 前端改动

两个面板的账户下拉框都增加一项“使用全局默认账户”，并在旁边显示当前全局账户名，例如“使用全局默认账户（Steve）”。实现方式是在 ViewModel 中增加 `[ObservableProperty] bool UseGlobalDefaultAccount`，勾选时禁用账户下拉框；这样不需要往 `UserModel` 列表里塞占位对象，编译绑定也更简单。

`NewGameDataPaneViewModel.cs`：

- 第 49 行的默认值逻辑保留，但 `UseGlobalDefaultAccount` 默认为 true。
- `Save()` 中，`UseGlobalDefaultAccount` 为 true 时传 `userModel: null`。

`EditGameDataPaneViewModel.cs`：

- 第 58-63 行：实例账户为 null 时设置 `UseGlobalDefaultAccount = true`，不再把全局账户写回实例；实例账户已被删除时同样切到全局选项，并给出提示。
- 第 90 行：保存时 `UseGlobalDefaultAccount` 为 true 存 null，否则存 `SelectedUser.UserID`。
- 约第 156 行的 `CopyThisInstance` 原样复制该字段，null 保持 null。

`NewGameDataPane.axaml` 和 `EditGameDataPane.axaml`：在默认用户下拉框上方加入“使用全局默认账户”复选框，下拉框的 `IsEnabled` 绑定到它的反值。

同时检查 `GameLaunchService.cs`、`OneLauncher/Codes/LaunchGame.cs` 中读取 `DefaultUserModelID` 的地方，改为通过 `ResolveLaunchUser` 获取账户。

## 五、边界情况

- 原版实例：复选框禁用，不会触发安装。
- 某个推荐模组没有当前版本的兼容文件：跳过并在结果中列出。
- 网络错误或用户在任务中心取消：已经下载的文件保留，提示部分完成。
- `mods` 目录不存在：安装前创建。
- 实例账户为空且全局默认账户也为空：启动时提示登录，不崩溃。
- 旧版配置文件：`Guid` 到 `Guid?` 兼容，无需迁移。
- AOT：只用源生成 JSON 和静态清单，不引入反射。

## 七、验证步骤

1. 编译 `OneLauncher.sln`，确认无错误。
2. 新建 Fabric 1.21.x 实例并勾选推荐模组，确认任务中心出现安装任务，`mods` 目录下载了 fabric-api、sodium 等文件且没有重复。
3. 新建 NeoForge 实例并勾选，确认下载的是 NeoForge 版本的文件；新建原版实例时复选框不可用。
4. 选择一个缺少兼容版本的游戏版本，确认被跳过的模组出现在提示中，实例仍然创建成功。
5. 新建实例时选择“使用全局默认账户”，确认配置中保存为 null；切换全局默认账户后启动，确认使用的是新的全局账户。
6. 删除实例绑定的账户后启动，确认回落到全局默认账户；同时没有全局默认账户时，确认提示登录。
7. 用旧版配置文件启动，确认已有实例的账户设置保持不变。
8. 测试完成后清理工作区内下载的游戏文件和测试实例。
