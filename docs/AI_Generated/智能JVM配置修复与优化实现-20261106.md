# 智能 JVM 配置修复与优化实现

日期：2026-11-06。

本实现依据同目录的《智能JVM配置修复与优化行动文档-20261106》，并按用户最新要求调整配置规则：UI 切换模式时完整替换 `DefaultSettings.MinecraftJvmArguments`，包括手工修改的字段；不增加旧格式迁移或字段合并。其他账户、下载、Java 路径和实例配置不属于 JVM 预设重建对象。

## 行为与算法

- 预设工厂只创建数据，不读取硬件。保守／标准／激进采用精简 G1，暂停目标 200ms，区域大小自适应，不默认开启 Aikar、NUMA、预触碰或固定年轻代比例。
- 启动阶段一次采样可用内存，全部按 MiB 计算。预留 `clamp(总量×10%,512,2048)`，剩余空间按 8GiB／16GiB 分段，比例 80%／40%／20%。64 位自动上限 16384MiB，32 位及未知位数上限 768MiB。
- 普通需求 2048MiB，有加载器需求 `3072+8×启用模组数`，模式倍率 0.75／1／1.25。最大堆取预算与需求中的较小值，向下按 128MiB 对齐。默认初始堆最多 512MiB，自动预算低于 512MiB 明确报错。
- 从实际游戏目录的 `mods` 枚举 jar／zip／litemod，不解压文件、不统计 disabled 文件。目录不存在为零；读取失败记录诊断。
- 手动 Xmx 可以超过自动 16GiB 上限。Xms-only 在预算内提高自动 Xmx；超预算、负值、无效单位或最终 Xms>Xmx 报错。支持标准堆参数及 MaxHeapSize／InitialHeapSize 别名。
- 内存未知时省略自动堆值，交给 JVM 自适应，此时不保证 16GiB 上限。macOS 通过异步、可取消的 sysctl／一次 vm_stat 采样，不把压缩页、活动页和 wired 页计入可用内存。

需求系数仍是启发式，不代表所有整合包的实测最佳值。服务端使用同一预算与原版基础需求，不使用客户端模组数量；玩家及世界负载调优留给显式设置。

## Java 与参数合并

JavaManager 提供实际运行时检查。启动时解析并固定实际可执行文件，PATH 回退检查命中的文件。读取 release 后必要时运行 `-XshowSettings:properties -version`；javaw 使用同目录 java 检测。输出／错误输出同时读取，单次进程最多 3 秒，可取消并终止探测进程。

缓存键包含可执行文件与 release 时间戳；成功结果缓存，失败结果仅缓存 10 秒。能力检查用 16／64MiB 小堆和 `-version`，不分配实际游戏堆。探测参数限制在已知 GC／调优家族，不将账户、agent、用户输出文件参数等交给检测进程。

默认已识别 HotSpot Java 8+ 使用 G1。OpenJ9／未知 VM 只生成标准堆；显式 HotSpot GC 无法确认支持时报告错误。显式 ZGC／Shenandoah／Aikar 参数经过能力探测，实验开关按版本及实际参数需要添加。ZGenerational 仅在 21／22 的结构化分代 ZGC 选择中生成，23+ 省略。

最终主类之前合并来源，优先级为：用户原始参数 > 结构化显式值 > 加载器 > 版本 > 自动默认。先决定生效来源再校验；同一来源的重复堆参数保留最后一个值，GC 逐项按最后一次启用／禁用处理并检查互斥。必须留在命令行的参数保持其位置；引号、模块、classpath、natives、javaagent 和游戏参数保留。

`None` 不生成启动器优化参数。服务端启动改为 RunAsync，仅等待参数检测和进程启动，不等待整个服务器生命周期；同时修正现有服务端入口的版本路径传参与 versions 拼写。

## UI 与配置

SettingsPageViewModel 加载选择状态时屏蔽 JVM 变更回调。用户主动切换时新建整份预设，串行等待保存，不合并手工字段；保存失败恢复原配置和选择，并沿用现有错误展示。

没有批量迁移历史文件或主动读取并重写用户磁盘配置。切换后 JSON 使用当前模型的全部预设值。既有非 JVM 设置初始化回调可能保存整个配置文件，这是原有行为；测试确认 JVM 内容在页面构造前后保持一致。

## 文件与扩展位置

核心改动在 JvmArgument、SystemMemoryHelper、JavaManager、ExtraJvmArgsBuilder、JvmArgsBuilder、LaunchCommandBuilder、GameLauncher 和 MinecraftServerManger。新增 JvmOptimizationPolicy、JavaRuntimeInfo、JavaRuntimeInspector，以及 ConsoleTest 的 internal 访问声明。

UI 改动在 SettingsPageViewModel、InitServerPaneViewModel 和 VersionPageViewModel。ConsoleTest 增加 `--jvm-config` 独立入口与 JvmOptimizationChecks。OneLauncher.csproj 增加 ConsoleTest 的 internal 测试访问；ConsoleTest.csproj 增加 `JvmConfigAotOnly` 条件，仅编译 JVM 检查，排除依赖 Debug 专用 setter 的历史集成夹具。检查使用直接调用，不依赖 UI 反射和裁剪保留。没有修改 Desktop 启动项目、AXAML 或产品第三方依赖；原有 MojangProfile 外部修改保持不动。

预算系数集中在纯策略函数；新增发行版／GC 支持可扩展运行时解析和有限能力检查。运行时快照不持久化，无需新增 JSON 元数据；当前 JVM 模型继续使用现有源生成上下文，新增产品代码没有反射或动态代码生成。
