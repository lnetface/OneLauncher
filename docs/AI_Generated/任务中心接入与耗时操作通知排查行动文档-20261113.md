## 1. 已有能力与结论

- `OneLauncher/Views/MainWindow.axaml.cs:30`：`MainWindowShowFlyoutMessage` 的第三个参数是 `openTaskCenterAfterClick`，默认 `false`。
- 同文件 `:181`：只有该值为 `true` 才设置通知的点击回调；`:188` 在当前实现了 `IPageHost` 的页面中显示任务中心。此值只负责打开任务中心，不负责创建任务或定位某条任务。
- `OneLauncher.Core/Global/TaskManager.cs:77`：创建任务并提供取消令牌；`TaskInstance` 提供进度、完成、失败、取消事件。
- `OneLauncher/ViewModels/Panes/TaskCenterPaneViewModel.cs:26`：已订阅创建与状态事件。任务列表显示状态并不意味着会弹出通知，目前没有全局自动任务通知机制。

后续使用具名参数，避免把通知类型、点击行为、标题混淆：

```csharp
WeakReferenceMessenger.Default.Send(new MainWindowShowFlyoutMessage(
    "开始执行……", openTaskCenterAfterClick: true));
WeakReferenceMessenger.Default.Send(new MainWindowShowFlyoutMessage(
    "操作完成……", NotificationType.Success, openTaskCenterAfterClick: true));
```

不会将消息构造函数的默认值统一改成 `true`：普通设置保存、输入校验、文件选择取消等消息没有相应耗时任务。

## 7. 实施验收标准

1. 有效用户输入确认后才建耗时任务；选择文件取消不留空任务。
2. 一次任务只发一次开始和一次实际终态通知；成功/取消/失败准确，不出现失败后成功消息。
3. 关联耗时任务的弹窗具名传入 `openTaskCenterAfterClick: true`；点击后当前页面打开任务中心且能看到对应任务。
4. 任务取消令牌传到底层操作，后台执行保持 UI 可响应；回调不得在终态之后继续写进度或改成成功。
5. 点击通知替换原侧栏后，原任务的关闭回调不得隐藏新任务中心；参考已有侧栏的 `ReferenceEquals(PaneContent, pane)` 保护，必要时仅在受影响入口补保护。
6. 不以启动外部进程当作外部工作全部完成；不以进入异步方法当作网络连接成功。
7. 使用现有静态类型、DI 和消息机制，保持 AOT 兼容。

本轮仅静态分析，无运行验证。后续小范围通知补齐按 AGENTS.md 可不运行测试；涉及取消/后端结果契约或多功能较大改动时执行必要构建及针对性验证。所有生成文件、测试数据和脚本留在工作区；若进行了实验，遵守项目清理要求。
