# 整合包导出生成远程下载链接 · 行动文档-20261119

> 触发方式：“说明执行”。本文只给出分析和执行计划，**没有修改任何代码**。  
> 依据：用户附件《Mod JAR 来源解析与整合包导出方案》、`docs/AI_Instruction` 中的全部规范、`docs/AI_Generated/后端代码设计规范.md`、`docs/AI_Generated/CurseForge资源获取与Modrinth现代化-20261119.md`。

## 1. 任务目标

1. 导出实例为 `.mrpack` 时，对 `mods/` 中的文件做哈希反查。能精确匹配平台文件的模组写入 `modrinth.index.json` 的 `files[]`（包括下载链接、SHA-1、SHA-512 和大小），不再打包进压缩包。无法识别的模组仍然放入 `overrides/mods/`。
2. 让导出代码现代化：改为异步 I/O，使用可空注解和 `long` 文件大小，按职责拆分，并把反序列化改为 AOT 源生成。
3. 把调用入口改为 `OneLauncher.Core.Services.ResourceInstallerService`，`ModpackExporter` 降级为 `internal` 执行组件。

## 3. 设计

### 3.1 解析流程（每个模组文件）

```text
扫描 <实例>/mods/*.jar 和 *.jar.disabled
  -> 第一遍读取：size + SHA-1 + SHA-512
  -> Modrinth：POST /v2/version_files {hashes:[sha512...], algorithm:"sha512"}
       在返回版本的 files[] 中按 sha512 精确匹配，并核对 sha1 和 size
  -> 仍未命中且 Init.CurseforgeApiKey 不为 null：
       第二遍读取，只为这些文件计算 CF Murmur2 指纹
       POST /v1/fingerprints/432，只接受 exactMatches
       核对 fileLength、SHA-1 和 fileFingerprint；downloadUrl 为空（作者禁止第三方分发）时视为未命中
  -> 仍未命中：放入 overrides/mods/<原文件名>
```

- **只依据哈希匹配**，不根据文件名或 modId 推测 URL（方案第 1、7 节）。
- 下载链接必须是 https，复用 `Download.CreateSafeItem` 中已有的 URL 校验逻辑。如果该校验是私有方法，就把它提升为 `internal static bool IsSafeRemoteUrl`，不另写一份。
- `.jar.disabled` 也参与反查，清单中的 `path` 保留 `.disabled` 后缀，导入后仍是禁用状态（方案验收用例 7）。
- CF 指纹只在 MR 未命中时才计算第二遍，大多数模组只需要读一次。

### 3.2 失败降级

| 情况 | 处理 |
| --- | --- |
| MR 或 CF 网络错误、限流、JSON 错误 | 该平台这一步按“全部未命中”处理，文件进入 overrides，导出继续，结果中记录一条警告 |
| 未配置 CF API Key | 跳过 CF 步骤，不报错，结果中记录一条提示 |
| 用户取消 | `OperationCanceledException` 直接向上抛出，清理临时文件（沿用现有逻辑） |
| 文件 I/O 错误 | 保持现在的处理：转换为 `OlanException("导出失败", ...)` |

这样做的理由是：远程链接只是优化手段，失败时导出结果仍然完整，只是包体积变大。同时警告会如实交给前端，不会把失败当作成功。

### 3.3 关于平台差异的说明

- 导出格式仍然只有 `.mrpack`，本次**不新增** CurseForge `manifest.json` 格式导出。
- `files[]` 中来自 CF 的条目，其 URL 是 `edge.forgecdn.net` 或 `mediafilez.forgecdn.net`。OneLauncher 和 Prism 都能正常导入这样的包，但**发布到 Modrinth 平台**时，可能因为下载域名白名单校验而被拒绝。这一点会写进实现文档。
- 方案第 5、6 节中的“用户自定义 URL 映射”和“候选确认界面”**不在本次范围内**，后续可以在解析流程末尾追加一个步骤。

## 6. 风险

- `POST /v2/version_files` 返回对象的键是传入的哈希，需要用源生成的 `Dictionary<string, ModrinthVersion>` 反序列化，已列入 JSON 上下文。
- 大实例（几百个模组）需要计算哈希，耗时主要在磁盘读取；计算有并发上限，并且可以取消。
- `ModpackExporter` 改为 `internal` 后，只要有外部程序集仍在直接调用它就会编译失败。已用 grep 确认只有 `EditGameDataPaneViewModel` 一处调用，回归测试中没有引用。
