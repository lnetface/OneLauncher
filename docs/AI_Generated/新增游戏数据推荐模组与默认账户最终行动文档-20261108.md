# 新增游戏数据推荐模组与默认账户最终行动文档（2026-11-08）

本文档取代 `docs/AI_Generated/新增游戏数据推荐模组与默认账户行动文档-20261107.md`。它基于用户已完成的后端改动（`GameLauncher.cs`、`DBManager.cs`、`GameData.cs`、`UserModel.cs`、`ResourceInstallerService.cs`，以及新增的 `RecommededMods/JsonModels.cs`、`RecommendedModInstaller.cs`、`Helper/Models/Than.cs`）做审查，并给出后续执行步骤。

按照 `docs/AI_Instruction/AGENT_MUST_READ_FIRST.md` 的分工，`OneLauncher.Core` 归人类维护，下文的后端修改都是**建议**，由人类确认或执行；`OneLauncher` 中的 `.axaml` 与 ViewModel 由 Agent 执行；`OneLauncher.Desktop` 不改动。

## 一、审查结论（按优先级）

### 1. 推荐模组列表没有初始化（最高优先级）

`DBManager.cs` 中 `DefaultConfig.RecommandedMods` 的初始值是 `new()`，项目里也没有任何地方写入默认推荐模组。结果是：新配置文件得到空列表，旧配置文件读出来也是空列表，勾选“一键安装所有推荐模组”后什么都不会安装，且不会报错。

另外，`OneLauncherAppConfigsJsonContext`（`DBManager.cs` 第 11–21 行）没有注册 `RecommendedMod`、`ModLimited`、`Than`、`List<RecommendedMod>`。在 AOT 发布下，这些类型可能无法序列化，或者 `Than` 被写成数字。

### 2. 编译错误

- `ResourceInstallerService.cs:17` 的 `InstallRecommendedMods(GameData data) => new RecommendedModInstaller(data).InstallAsync();` 无法编译：`RecommendedModInstaller` 的构造函数是 `private`，参数是 `(GameData, ModLimited)`，这里只传了一个参数；同时缺少进度回调和取消令牌。
- `RecommendedModInstaller` 是 `internal`，而 `ResourceInstallerService` 对外暴露它的调用，访问级别需要统一。
- `GameData.DefaultUserModelID` 改为 `Guid?` 之后，`EditGameDataPaneViewModel.cs:58` 的 `GetUser(...)` 调用和第 156 行附近对 `Guid` 的使用需要跟着调整，否则前端编译失败。

### 3. 推荐模组的筛选与下载逻辑

- 构造函数接收的 `limited` 没有被使用。
- 下载时使用的是每个推荐项自带的 `minecraftVersion` 和 `modLoader`，应该使用实例自身的 `VersionId` 和 `ModLoader`。推荐项的限制条件只用来判断“这个模组适不适用于此实例”。
- `Than` 枚举没有参与比较，版本限制实际不生效。另外 `GreaterThan` / `LessThan` 只能表达单边条件，也不清楚是否包含等号。建议改为可空的 `MinVersion` / `MaxVersion`（闭区间），比较时使用项目已有的 Minecraft 版本比较工具。
- 安装目录写成了相对路径 `Path.Combine(InstanceId, "mods")`，会装到进程工作目录下。应使用实例的绝对路径 `Path.Combine(gameData.InstancePath, "mods")`，并在写入前创建目录。
- 惰性 `Select` 被枚举了三次，会重复发出 Modrinth 请求。应先 `.ToList()`。
- `!.Value` 在 Modrinth 找不到匹配文件时会抛出异常。没有匹配版本属于正常情况，应记为“跳过”。
- `Task.WhenAll` 让一个模组失败就使整批失败。应逐个收集结果：已安装、已跳过（不兼容或无文件）、已存在、失败（附错误信息）。
- 依赖项与推荐项之间可能重复（例如多个模组都依赖 fabric-api），需要按 ProjectId 去重，并跳过 `mods` 目录中已存在的同名文件。
- 代码同时使用 `Init.*` 和 `UnitedCore.Core`，建议统一为注入的 `UnitedCore` 或统一使用 `Init`。

### 4. 默认账户为空

- `GameData.cs:62` 的构造函数使用 `userModel ?? GetDefaultUser().UserID`，传入 `null` 也会被替换成全局默认账户，“设为空”无法保存。
- `GameData.GetUserModelForLaunching()`（第 34–38 行）在已保存的账户被删除时直接抛出异常。旧逻辑会回退到全局默认账户，现在行为变严格了。建议回退到全局默认账户，并通过返回值或日志提示“原账户已不存在”。
- `GameLauncher.cs` 中 `IntelligentLogin` 的结果赋给了 `Task resh`，刷新后的用户对象可能没有被用于构造启动参数，需要 `await` 后使用其结果。
- `AccountManger.cs:62` 的 `GetDefaultUser()` 声明为非空，但 `AccountPageViewModel.cs:62` 把它当可空值处理。需要确定没有任何账户时的行为（建议返回 `null`，启动时给出“请先添加账户”的提示）。
- 以下调用目前会显式写入全局默认账户 ID，应改为传 `null`，让新建的游戏数据默认跟随全局账户：

| 文件 | 行 |
| --- | --- |
| `OneLauncher.Core/.../DownloadInfoCreater.cs` | 53、55、57、59、61 |
| `OneLauncher.Core/.../ModpackImporter.cs` | 93 |
| `OneLauncher.Core/Global/ModelDataMangers/GameDataManger.cs` | 114 |
| `OneLauncher.Core/.../ImportPCL2Version/ImportMain.cs` | 52 |
| `tests/OneLauncher.RegressionTests/LaunchWorkingDirectoryChecks.cs` | 80 |

- `GameArgsBuilder.cs:16` 已经有回退到全局默认账户的逻辑，可以作为统一行为的参照。
- `UserModel.cs` 中新改的注释与实际行为不符，需要更正。

### 5. 命名

`RecommededMods`（文件夹与命名空间）、`RecommandedMods`（属性）存在拼写错误；`ModLimited` 的字段 `modLoader`、`minecraftVersion`、`operation` 使用了小写。建议在首次发布前统一改为 `RecommendedMods`、`ModLoader`、`MinecraftVersion` 等。注意属性名会写入配置 JSON，发布后再改名需要迁移，所以应尽早决定。

## 二、推荐模组列表初始化方案（人类执行）

`BasicDataManager<T>`（`OneLauncher.Core/Global/ModelDataMangers/BasicDataManger.cs`）在文件不存在时写入 `new T()`，否则读取文件，两种情况最后都会调用 `PostInitialize()`。`Init.cs` 调用 `configManger.InitializeAsync()` 时没有传入初始数据。据此分三层处理：

1. **默认目录**：在 `RecommededMods` 文件夹新增 `RecommendedModCatalog.cs`，提供 `public static List<RecommendedMod> CreateDefault()`，每次返回新列表，避免共享可变实例。
2. **属性初始值**：把 `DefaultConfig` 中的声明改为 `public List<RecommendedMod> RecommandedMods { get; set; } = RecommendedModCatalog.CreateDefault();`。这样新配置文件、以及 JSON 中缺少该属性的旧配置文件都会得到默认列表。
3. **旧配置迁移**：在 `DBManager` 中重写 `PostInitialize()`。当 `Data.DefaultConfig.RecommandedMods` 为 `null` 或为空时，用 `CreateDefault()` 填充并 `await Save()`。这一步覆盖已经写入 `[]` 的旧配置。
4. **可选的目录版本号**：在 `DefaultConfig` 增加 `int RecommendedModsCatalogVersion`。启动器升级推荐列表时提高版本号，`PostInitialize()` 发现配置中的版本较低就合并新增项。若希望用户可以删除推荐项而不被自动补回，就必须用这个版本号，而不能只判断“列表为空”。
5. **AOT 注册**：在 `OneLauncherAppConfigsJsonContext` 添加 `[JsonSerializable(typeof(RecommendedMod))]`、`ModLimited`、`List<RecommendedMod>`，并为 `Than`（或替换后的区间类型中的枚举）加上 `JsonStringEnumConverter<T>`，让配置文件可读。
6. **null 防御**：`ValidateData()` 在每次读写时调用，可以在其中把 `null` 列表替换为空列表，避免后续代码出现空引用。

建议的数据形状（采用区间限制后）：

```csharp
public record struct RecommendedMod(string ProjectId, ModLimited Limited);
public record struct ModLimited(ModEnum ModLoader, string? MinVersion, string? MaxVersion);
```

建议的默认目录（ProjectId 以 Modrinth slug 表示，写入前需要逐个在 Modrinth 核对）：

| 加载器 | 模组 |
| --- | --- |
| Fabric | fabric-api、sodium、lithium、iris、modmenu |
| Quilt | qsl（或 fabric-api）、sodium、lithium、modmenu |
| Forge / NeoForge | embeddium、modernfix、ferritecore |

部分模组只支持较新的版本（例如 embeddium、iris），需要在 `MinVersion` 中写明，否则低版本实例会大量出现“跳过”。

## 三、后端修复清单（人类执行）

1. `RecommendedModInstaller` 改为 `public`，构造函数改为 `public RecommendedModInstaller(GameData gameData, IReadOnlyList<RecommendedMod> mods)`，删除未使用的 `ModLimited` 参数。
2. `InstallAsync(IProgress<...>? progress, CancellationToken token)` 返回结果汇总（例如 `RecommendedModInstallResult`，包含已安装、已跳过、已存在、失败四类列表）。

4. `ResourceInstallerService` 改为：

```csharp
public Task<RecommendedModInstallResult> InstallRecommendedModsAsync(
    GameData data, IProgress<...>? progress, CancellationToken token)
    => new RecommendedModInstaller(data, Init.ConfigManger.Data.DefaultConfig.RecommandedMods)
        .InstallAsync(progress, token);
```

5. `GameData` 构造函数保留 `null`；`GetUserModelForLaunching()` 在账户缺失时回退到全局默认账户。

7. `GameLauncher` 使用 `await` 后的刷新用户对象。
8. 明确 `GetDefaultUser()` 的可空性，并更正 `UserModel.cs` 注释。
